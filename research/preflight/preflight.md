## 10. NEAR AI Cloud signed responses
GET /v1/signature/{chat_id}?signing_algo=ecdsa|ed25519 (default ecdsa; Bearer key). ecdsa = secp256k1 Ethereum EIP-191 signature, signing_address an ETH address; ed25519 = signature over the UTF-8 `text`, signing_address the hex pubkey. Signed text: provider_tee `<MODEL_ID>:<sha256(exact request bytes)>:<sha256(exact response bytes)>`; gateway signature (streams, aliases, Responses API) `<req_hash>:<resp_hash>`. Send canonical model id, x-no-aliasing:true, Accept-Encoding identity, hash raw bytes. All instances of a model share one key.
On-chain: ed25519 verifies with env::ed25519_verify over `text`; ecdsa needs keccak256 of the EIP-191-prefixed text + env::ecrecover. The OutLayer app can check either. The key's TEE binding comes from the attestation quote (nonce + signing_address in report data), which a contract cannot check; pin the key and publish the quote.
Redact exists: POST /v1/privacy/redact, body {model:"openai/privacy-filter", input:string|string[], threshold?}; 200 {data:[{index, redacted, usage}], id, model} (id works at /v1/signature/{id}); PII replaced by dummies; Bearer key; billed on input tokens ($0.01/M). Also /v1/privacy/classify.
Decision: signing_algo=ed25519; the app stores {text, signature, key, quote} with each decision.
Unverified: a live signed completion or redact call (no key, none made).
