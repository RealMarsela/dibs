# Lane A handback: contracts

Interface for the other lanes: `contracts/INTERFACE.md` (message formats, methods, gas, error codes).
Everything here ran in the near-workspaces sandbox or on testnet. Nothing touched mainnet.

## What exists

| path | what |
|---|---|
| `bed/` | raw `no_std` wasm, one method `sweep{amount}`, parses its own id, calls `usdc.ft_transfer_call` with 1 yocto. USDC id baked at build (`DIBS_USDC`, default mainnet USDC) |
| `dibs/` | near-sdk 5.17 contract, one for all trips (modules: `trip`, `pay`, `oracle`, `refund`, `types`, `util`) |
| `usdc-test/` | testnet NEP-141 (6 decimals) with open `mint` (cap 1000 USDC per call). Never for mainnet |
| `mock-outlayer/` | sandbox stand-in for `outlayer.near`: returns a staged response, refunds unused deposit |
| `tests/` | near-workspaces sandbox suite (own crate, nightly toolchain because near-workspaces 0.24 needs rustc 1.95) |
| `scripts/` | `build.sh`, `fetch-sputnik.sh`, `deploy-testnet.sh`, `seed-lisbon.sh`, `dao-policy.json`, `near-lib.sh` |
| `judge-report.json` | generated by `tests/tests/judge.rs`; `{checks:[{name, expected_code, ok}]}` plus `unmet_or_unenforced` |

Run: `scripts/fetch-sputnik.sh && scripts/build.sh sandbox && (cd tests && cargo test)`. The sandbox uses the real
Sputnik v2 DAO wasm (fetched from a live testnet DAO, not committed) so the `add_proposal` + `act_proposal`
chain and the `trip` role are exercised against the real contract.

## Tests (real output is in the final message of the session; re-run to reproduce)

- `tests/happy.rs`: 8 beds funded, draw, proof, payout through the DAO.
- `tests/judge.rs`: every attack from the brief with exact codes, 40+ checks, pot-untouched assertions, refund path.

## Sizes

| artifact | bytes | target |
|---|---|---|
| `bed.wasm` | see final message | <= 8 KB, met |
| `dibs.wasm` | see final message | <= 110 KB, NOT MET |

The 110 KB target is not reachable with this feature set on stable Rust 1.86 and near-sdk 5.17. The probe from
the preflight (10 methods) was already 111 KB; this contract has about 30 exported methods plus the resale,
waitlist, VRF, proof and refund logic. I removed `serde_json::Value`/`json!` and `format!` from the hot paths
(-10 KB) and measured `opt-level` s/3 (worse). Nightly `build-std` with `panic=immediate-abort` did not link
in this toolchain (undefined host imports), so it is untried. Cost on mainnet: storage is 1 NEAR per 100 KB,
locked and refundable, so about 2.8 NEAR for the wasm. Options if that is too much: drop `retry_payout`,
`release_hold`, `set_paid_from`, `get_config` (about 15 KB), or split waitlist/resale into a second contract.

## Decisions where the brief could not be followed literally (closest honest design)

1. **Callbacks do not take `(sig, output)`.** OutLayer returns the app output as the promise result, so
   `on_draw` / `on_proof` read it from the promise (same as the standin blocklist). Output shape: `{"message","signature"}`.
2. **Rejections inside callbacks are stored, not panicked.** A panic there would lose the caller's deposit.
   The code goes to `get_trip().last_error` and an `EVENT_JSON` log; the dry-run view `check_proof` returns the code too.
3. **Trip needs dates.** `create_trip` gained `check_in`, `check_out` (the proof must match them), `n_wait`, `stay`.
4. **`hold` needs a holder.** A bed can only be paid while Held (an Open bed has no known holder), so `ft_on_transfer`
   returns `E_NOT_HELD` for Open beds. `hold` is limited to the holder or a relayer (else anyone could squat beds).
5. **Waitlist buyers and resale buyers are reserved first** (`reserve_wait`, `hold` on a Listed bed) because the
   `{kind,trip,n}` message from the bed account cannot name the buyer.
6. **Replay protection added:** a `booking_ref_hash` is accepted once across all trips (`E_REPLAY`).
7. **Refunds are batched** (`limit` 1..3 per call) because each DAO Transfer needs about 80 Tgas of chained calls.
   A failed individual refund proposal is not retried automatically (gap).
8. **Payout is only `Done` after the DAO proposal reads back `Approved`**; the DAO swallows a failed `ft_transfer`
   into proposal status `Failed`, so `act_proposal` returning is not proof. `retry_payout` re-runs a stuck step.
9. **Currency:** `total` must already be micro-USD (the verifier converts); `currency` is informational.
10. The USDC feature flag is a build-time env var (`DIBS_USDC`) instead of a cargo feature, because the testnet and
    sandbox USDC ids are random per deployment.

## Known gaps (unverified or not built)

- `create_trip` does not verify the DAO's policy on-chain; the coordinator must create DAOs from `scripts/dao-policy.json`.
- The leftover pot (pot minus the booking total) stays in the DAO; there is no automatic return to funders.
- Excess USDC delivered to a bed account beyond `price` is stuck there.
- OutLayer is mocked in tests. The real `request_execution` gas (150 Tgas) and callback gas (100 Tgas) are copied from
  the standin and unverified against the live worker. Lane B's public key must be pinned with `set_verifier_key`
  and the project with `set_outlayer`.
- 1Click delivery to a keyless sub-account and its USDC storage registration was not exercised (preflight flagged it).
- Testnet DAO creation through `sputnik-v2.testnet` needs about 6 NEAR (it publishes 470 KB of code per DAO); the
  mainnet factory uses a global contract and is far cheaper (preflight section 2).
